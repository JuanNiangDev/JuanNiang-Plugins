# arxiv-summary arXiv 论文总结插件

识别群聊/私聊中发送的 arXiv 链接，自动抓取论文元数据，由主程序 LLM 翻译标题与摘要，按固定格式输出。

## 触发方式

直接发链接即可，无需命令。`/abs/`、`/pdf/`、`/html/` 三种页面都支持：

```
https://arxiv.org/abs/2611.25400
https://arxiv.org/pdf/2605.10310
https://arxiv.org/html/2609.16247v1
```

所有形式统一归一化为 `https://arxiv.org/abs/<id>` 抓取（带版本号 `v2`、`.pdf` 后缀、query 参数都会被剥掉），只看 abs 页的 `citation_*` meta：

- `citation_title` / `citation_author`（多个）/ `citation_abstract` / `citation_pdf_url`
- 学科取自 `<span class="primary-subject">` 与 `tablecell subjects` 单元格

**不解析 PDF 正文**：abs 页已包含完整摘要，抓取更快也更稳，不受 PDF 文本层缺失影响。

## 输出格式

```
📄 标题原文
🌏 标题翻译
👥 作者（超过 max_authors 位时前 N 位 + et al.）
🧠 摘要翻译（忠实翻译，不概括不点评）
🏷️ 人工智能 (cs.AI) · 机器学习 (cs.LG)
🔗 https://arxiv.org/abs/2611.25400
📄 https://arxiv.org/pdf/2611.25400
```

- 标题行尾附**零宽水印**（编码 `Generated by JuanNiang Neo`），转发回群的本机输出会被识别并跳过，避免二次总结。
- 学科中英对照，常用分类内置中文名；未收录分类回退英文名 + 原始代码；超过 `max_categories` 折叠为「等 N 类」。
- LLM 不可用时省略 🌏 / 🧠 两行（🧠 回退截断后的英文摘要），其余照常发送。

## 攒批与投递

- 同一群/同一人的链接进入缓冲区，首条起算 `batch_window`（默认 60s），攒满 `batch_threshold`（默认 3 篇）立即发送。
- 只有 1 篇时等待 `single_window`（默认 10s），期间来第 2 篇自动延长到攒批窗口。
- 一批 ≥ 阈值 → **一条合并转发**，每篇一个节点；不足阈值或 `merge_forward=false` → 每篇一条普通消息（首条引用原消息）。
- 抓取失败（网络 / 代理波动 / 404 / 解析失败）**整批静默**，不回复任何消息；部分失败只发成功的篇目。

## 缓存与去重

- 每篇论文一条缓存（元数据 + 翻译），TTL `cache_hours`（默认 168 小时）；命中缓存直接发送，不抓取不调 LLM。
- 在途去重：`dedup:<id>` 标记防止同一篇被多条消息重复处理，发送后清理。

## 文件结构

```
arxiv-summary/
├── main.lua     链接解析 → 异步抓取 → abs 页解析 → LLM 翻译 → 攒批投递
├── config.yaml  运行配置（Web 面板可改，即时生效）
├── pluggin.yaml 插件元数据（onebot11 / http / cache / llm / timer）
├── avatar.png   插件图标
└── README.md    本文档
```

## 主要配置

| key | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `enable_summary` | true | 关闭则只输出元数据，不调 LLM |
| `max_links` | 3 | 单条消息最多处理的链接数 |
| `max_authors` | 3 | 作者上限，超出追加 `et al.` |
| `max_categories` | 4 | 学科展示上限 |
| `cache_hours` | 168 | 结果缓存小时数 |
| `llm_timeout` | 90 | LLM 超时秒数 |
| `batch_window` / `batch_threshold` / `single_window` | 60 / 3 / 10 | 攒批策略 |
| `merge_forward` | true | 合并转发总开关 |
| `proxy` | 空 | 抓取代理，留空直连 |
| `group_only` | false | 只处理群聊 |

## 测试

本地用 lupa 桩化 `jn`（`http.get_async` / `llm.chat_async` / `timer.after` / cache / onebot11），覆盖链接归一化、abs 页解析、攒批阈值、合并转发降级、水印识别、失败静默、缓存命中、LLM 输出异常回退等场景。

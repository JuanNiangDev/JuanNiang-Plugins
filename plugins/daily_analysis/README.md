# daily_analysis 群聊日常分析与总结

复刻自 `astrbot_plugin_qq_group_daily_analysis`，专为 **JuanNiang-Neo** 架构深度定制的模块化智能群聊日常分析插件。

## 文件结构

```text
daily_analysis/
├── main.lua       消息采集、队列调度、定时巡检与主流水线
├── common.lua     配置读取、UTF-8 首尾截断、JSON 容错解析、零宽水印编解码与清洗
├── sources.lua    CQ 码编号展开（转发/图片/回复）与严格水印来源采集
├── enrich.lua     开源项目非 LLM 官方 API 元数据补全 + 公众号正文异步抓取与摘要
├── prompts.lua    人设读取、主分析 / Map 切片 / Reduce 提示词（含图片转发关联与谐音梗识别）
├── mapreduce.lua  Map-Reduce 分段提炼与多级递归敏感审查拆片挽救
├── report.lua     橘鸦比对与公众号新闻合并、AI 监控汇总、板块组装与合并转发投递
├── juya.lua       橘鸦 AI 早报抓取与 HTML 解析
├── config.yaml    Web 管理后台配置架构
└── pluggin.yaml   插件元数据与权限声明
```

## 核心功能

1. **模块化板块与投递模式**（`report_mode` / `sections`）：
   - 支持 `forward`（合并转发，默认）、`per_section`（按板块发）、`per_item`（按条发），多群任务按近 24h 消息数**小群优先**串行排队，且**仅在发回本群的正式日报成功后**才锁定当天自动定时防重（私聊/跨群测试不阻断当晚定时；失败不锁次日调度）。
   - 默认板块顺序（均支持 `key|标题|条数上限` 自定义）：
     `overview` → `top`（发言主力军，默认 `top_users_count = 5` 人）→ `topics` → `quotes` → `titles` → `critique` → `projects` → `ai_monitor`（近 24h 全平台 AI 重置与官方状态监控汇总）→ `news` → `stats`。

2. **Map-Reduce 长聊分段与递归敏感隔离（含分阶段看门狗续期）**：
   - 语料字符数超过 `map_reduce_threshold`（默认 `50000`）时自动按 `map_chunk_chars`（默认 `35000`，最多 `8` 段）切换至 2 并发 Map-Reduce 模式，并按并发轮数动态核定看门狗预算、在每片 Map 完成与 Reduce 启动时自动顺延，防止大群前序耗时挤占 Reduce 回调窗口。
   - 若单次请求或某个 Map 切片命中上游敏感内容审查，自动触发**最多两级二次拆片（默认 `map_resplit_max_depth = 2`，即失败最多分片两次、共 3 次尝试机会；范围 `0~3`）**精准隔离违规句并保留其余所有讨论：
     - 二级拆片 `map_resplit_count`（默认 `8`，后台可配，`0`/`1` 关闭，上限 `32`）
     - 三级拆片 `map_resplit_l2_count`（默认 `4`）
     - 四级拆片 `map_resplit_l3_count`（默认 `2`，当 `map_resplit_max_depth=3` 时启用）
     - 最大拆片级数由 `map_resplit_max_depth`（默认 `2`）控制。

3. **严格零宽水印检索与零 LLM 开源项目搬运**：
   - 仅依据零宽水印（同时兼容 `Generated by JuanNiang Neo` 与 `Generated By JuanNiangNeo`）识别群内或合并转发中的 `repo-intro` / `wechat-article-summary` / `ai_reset_monitor` 机器人产出，**不靠 emoji 猜测**。
   - 所有送入 LLM 的消息流与正文均会先清洗剥离零宽水印，避免占用过长上下文和干扰模型总结。
   - 开源项目列表板块**全程不调用 LLM**：有水印的 `repo-intro` 卡片直接原样照搬（含配图），无水印的裸链接仅调 GitHub / Hugging Face / ModelScope 官方 API 补基础元数据。

4. **橘鸦与公众号新闻对比（标记原样搬运 + 重合合并）**：
   - 同时采集独立分享及**合并转发内嵌**（JSON/XML 卡片、带水印摘要、嵌套链接）的公众号文章与当日橘鸦 AI 早报。
   - 仅橘鸦独占的新闻，合比 LLM 仅返回一个 `juya_id` 标记，代码直接**原样搬运**橘鸦标题、完整正文 `detail`（无正文回退 `summary`）与全部来源链接；与公众号重合的新闻由 LLM 将公众号内容合入橘鸦并去重汇总全部来源链接。

5. **图片与合并转发编号关联 + 谐音梗/黑话识别**：
   - 为聊天流中每张图片（含**合并转发内层图片**）和每条合并转发分配连续编号（`[图#k：...]`、`[转发#k｜N条]`），单份报告视觉描述上限默认放宽至 `30` 张，回复引用展开保留前 `140` 字上下文。
   - 提示词要求每个分片及主总结独立归纳关键图片与转发内容，明确标注话题/金句围绕哪个 `[图#k]` 或 `[转发#k]` 展开，并支持识别网络黑话与谐音梗适当融入话题和金句。

6. **每日多平台 AI 重置与官方状态监控汇总**（`ai_monitor`）：
   - 直接读取 `pluggin_ai_reset_monitor_seen` 表过去 24h 全平台已监测到的重置与官方服务故障/恢复事件，统一汇总展示在「今日新闻」之前。

## 权限与持久化

- 权限：`onebot11`、`database`、`llm`、`agent`、`timer`、`cache`、`http`、`file`
- 持久化表：`pluggin_daily_analysis_messages`（消息默认保留 7 天）与 `pluggin_daily_analysis_reports`（报告默认保留 90 天）。

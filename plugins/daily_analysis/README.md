# daily_analysis 群聊日常分析与总结

复刻自 `astrbot_plugin_qq_group_daily_analysis`，专为 **JuanNiang-Neo** 架构深度定制打造的智能群聊日常分析插件。

## 功能特色

1. **板块化日报，拆分 / 合并可选**（`report_mode`）：
   - `forward`（默认）：整份做成**一条合并转发**卡片，节点为「板块标题 + 每个条目」，板块与条目之间不再插入 `---` 分隔气泡。
   - `per_section`：每个板块合成一条消息（超长自动按行切块）。
   - `per_item`：每个条目单独一条消息（条数多，容易刷屏）。

2. **板块顺序 / 标题 / 条数全部可配**（`sections`，每行 `key|标题|上限`）：
   - key：`overview` `top` `topics` `quotes` `titles` `critique` `projects` `news` `stats`
   - 上限 `0` 关闭该板块、`-1` 不限、正数为最多几条；行序即发送顺序。

3. **「开源项目列表」= repo-intro 原文优先 + 官方 API 兜底**：
   - 只取群里本机 repo-intro 发过的卡片消息（零宽水印校验），正文**原样照抄**：`📦 名称` / `📝 标题` / 简介段落 / 链接。
   - 每条仓库后面跟着的那张卡片图会一起转发；一条消息里塞了多个仓库（段序 `text1,img1,text2,img2`）时按 `📦` 拆块，**图片只挂到它前面那个仓库**。
   - 群友分享、但当日窗口里没出现卡片的仓库，先查 repo-intro 的成品缓存（中文标题 + 简介 + 卡片），命中原样复用；未命中才调用 GitHub / HuggingFace 官方 API 补真实 description / 指标（404 剔除）。
   - 补全默认全量执行，没有开关、没有条数上限。

4. **新增「今日新闻」**：
   - 来源一：群内分享的微信公众号文章（按分享次数统计，复用 wechat-article-summary 已生成的标题与总结）。
   - 来源二：橘鸦 AI 早报当日一期（`news_feeds` 可配，默认 `rss.xml` + `issues/{date}/`，当天页缺失自动回退 RSS 最新一期）。
   - `news_event_merge` 开启时，用 LLM 把描述同一事件的公众号文章与早报条目合并成一条，并保留**全部来源链接**（公众号原文 + 早报来源）；失败自动降级为顺序罗列。
   - 条数上限由 `sections` 里 `news` 的第三段控制（默认 70）；标题自动带条数（`📰 今日新闻（12条）`），条目用中文序号「一、二、三、」。

5. **水印识别，不重复总结**：
   - 带 `Generated by JuanNiang Neo` 零宽水印的消息是本机插件产出，**不参与聊天分析**，只用来提取标题与已有总结；兼容旧版 4 字符标记。

6. **不自带渲染，轻量**：
   - 插件本身不依赖 T2I 渲染服务；日报里的项目卡片图直接转发 repo-intro 已经渲染好的成品图。

7. **后台全功能可视化配置**：
   - 多选群聊白名单、每日定时（默认 23:00，统计前 24 小时）、话题/金句/头衔/维度数量、人设强度、进度提示开关、一键立即触发。

8. **安全轻量的数据流**：
   - 专属消息表，默认保留 7 天轮转，分析后自动清理。

## 权限

`onebot11` `database` `llm` `agent` `timer` `cache` `http`（http 用于抓取橘鸦早报）


## 搬运消息语料展开（合并转发 / 图片 / 回复）

群里不少讨论围绕转发的文章或图片展开，原始 CQ 码（`[CQ:forward,id=...]`、
`[CQ:image,url=...]`、`[CQ:reply,id=...]`）对总结模型没有语义。生成语料前会：

- **合并转发**：调用 `jn.onebot11.get_forward_msg_sync(id)` 读取内层节点，
  按「昵称：正文」展开（默认最多 10 条、每条 120 字），按 ID 缓存 7 天。
- **图片**：调用 `jn.llm.vision_url("wb-api-image", url, prompt)`，由图像模型
  给出一句话描述（默认每份报告最多 10 张），按 URL 缓存 7 天；失败或超限记 `[图片]`。
- **回复**：查本地消息库，把被回复消息的前 80 字作为上下文拼进语料。
- **语音 / 视频 / 文件**：只留 `[语音] / [视频] / [文件]` 占位，内容不入库。

相关配置：`expand_forward`、`forward_node_limit`、`forward_node_chars`、
`vision_describe`、`vision_provider`、`vision_image_limit`、`expand_reply`。

## 来源复用（repo-intro / 公众号总结）

「开源项目列表」和「今日新闻」不再让 LLM 重新猜，直接复用群里已经发过的本机总结：

- **bot 输出入库**：`filter_bot_messages` 只拦普通回复；带零宽水印的本机输出
  （repo-intro 卡片、公众号总结）会写入消息表，作为来源索引。分析语料、统计、
  话题、金句一律按 `user_id == bot` 排除，不会自我总结。
- **合并转发要展开**：公众号总结按 `merge_forward` 合并转发下发，`raw_message`
  只有 `[CQ:forward,id=…]`，水印在节点正文里。入库与采集时会全量展开节点
  （不截断、保留换行），再按 `📰 标题` / 摘要 / `🔗 原文链接` 解析，按 URL
  关联到群内分享的链接。
- **拿不到标题的裸链接不进新闻正文**，日志输出 `新闻过滤：N 条无标题链接未进正文`。
- **开源项目就是 repo-intro 原话**：`📦 名称` / `📝 标题` / 简介 / 链接逐字照抄，并带上该仓库的卡片图；
  没被 repo-intro 介绍过的仓库不会出现在日报里（不再调 GitHub / HF API 补简介）。

## 报告持久化

每次成功发送后，日报会写入 PostgreSQL 表 `pluggin_daily_analysis_reports`（来源群、投递目标、日期、模式、板块数、节点数、板块 JSON、正文），跨容器/插件重启可查；`report_retention_days` 默认保留 90 天。群消息表 `pluggin_daily_analysis_messages` 同样持久化（默认 7 天）。

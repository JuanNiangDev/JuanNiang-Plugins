# x-status-summary

X（推特）链接总结插件。给一条消息里的 `x.com` / `twitter.com` 状态链接（含 `/i/status/<id>`）自动抓取内容并总结。

## 行为

| 场景 | 输出 |
|------|------|
| X 长文（article） | 公众号样式：`📰 标题` / `📖 作者` / 总结 / `🔗 原文链接` + 封面 + 正文图片 |
| 普通推文 | 作者 → 一句话标题 → 总结 → 链接（纯文本，无行标 emoji） |
| 信息量不足（纯情绪/几个字/纯转发语） | 不总结，原样转发：作者 + 原文 + 图片 + 链接 |
| 引用推文 / 回复他人 | 总结里写清「谁说了什么、本条如何回应」（只追一层） |
| 推文里含 GitHub 链接 | 额外单独发一条仓库消息（`📦 owner/repo` + 摘要 + `card-5` 卡片图） |
| 推文里的其它外链 | 不抓取、不展开；只保留推文正文里的呈现 |
| 视频 | 时长 ≤ `video_max_seconds`（默认 600s）且估算体积 ≤ `video_max_mb`（默认 50MB）时以**独占一条**的视频消息发送，否则只发链接；上传失败自动降级为原推链接 |

文本与仓库标题行尾会附零宽水印（编码 `Generated by JuanNiang Neo`），用来识别本机输出，避免转发回来时二次总结；同时兼容旧版 4 字符标记。

## 数据来源

- 推文：`api.fxtwitter.com/status/<id>`（公开 JSON，含正文、作者、媒体、article 全文、引用推文、link facets）
- 仓库：`api.github.com/repos/<owner>/<repo>` 与 `.../readme`（可配 `github_token` 提高限流）
- 卡片：主程序 T2I 服务渲染 `templates/card-5.html`

> 服务器（国内）无法直连 `pbs.twimg.com` / `video.twimg.com`，图片与视频 URL 由 OneBot 侧拉取；
> 部署到无外网环境时需要自备代理或改写 URL：
> - `proxy_image_rewrite=https://wsrv.nl/?url=`（图片，实测协议端可拉取）
> - `video_url_rewrite=http://172.27.0.1:5284/video?url=`（本地媒体代理走 socks5）

## 发送策略（多媒体推文）

1. **正文 + 图片** 合并成一条消息先发（同步发送，失败自动降级为**纯文本**重发，保证总结一定送达）；
2. **视频独占一条**，放在正文之后发；上传失败（如 `highway upload ... TCP connect timeout`）自动降级成「视频发送失败，原推：<链接>」；
3. 视频因超时长/超体积没有选中时，正文末尾补一行「视频超限未发送，原推：<链接>」；
4. 引用节点只在消息 ID 有效（非 0）时添加，避免协议端 `could not quote the target message` 导致整条发送异常。

## 配置

见 `config.yaml`：包含总开关（`enabled`/`enable_summary`/`group_only`/`reply_quote`）、媒体开关与代理改写（`send_media`/`max_images`/`video_enabled`/`video_max_seconds`/`video_max_mb`/`proxy_image_rewrite`/`video_url_rewrite`）、仓库卡片联动（`repo_card`/`github_token`）、抓取接口与网络代理（`api_base`/`proxy`）、以及链接上限、LLM 超时、缓存 TTL 与手动测试（`manual_trigger`/`test_links`/`test_group`/`test_video_only`）。

## 异步流水线

```
on_message          → 解析 X 链接（去重/在途去重/缓存命中）
on_http_response    → xmeta（推文 JSON）→ xparent（被回复推文）→ ghmeta → ghreadme
on_chat_response    → 推文总结 / 仓库总结 → 触发卡片渲染
on_t2i_response     → 收集卡片 URL
finish              → 先发推文消息，再逐条发仓库消息
```

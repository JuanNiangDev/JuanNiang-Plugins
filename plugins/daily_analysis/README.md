# daily_analysis 群聊日常分析与总结

复刻自 `astrbot_plugin_qq_group_daily_analysis`，专为 **JuanNiang-Neo** 架构深度定制打造的智能群聊日常分析插件。

## 功能特色

1. **板块化日报，拆分 / 合并可选**（`report_mode`）：
   - `forward`（默认）：整份做成**一条合并转发**卡片，节点为「板块标题 + 每个条目」，板块与条目之间不再插入 `---` 分隔气泡。
   - `per_section`：每个板块合成一条消息（超长自动按行切块）。
   - `per_item`：每个条目单独一条消息（条数多，容易刷屏）。

2. **板块顺序 / 标题 / 条数全部可配**（`sections`，每行 `key|标题|上限`）：
   - key：`overview` `top` `topics` `quotes` `titles` `critique` `projects` `news` `stats`
   - 上限 `0` 关闭该板块、`-1` 不限、正数为最多几条；行序即发送顺序。

3. **新增「开源项目列表」**：
   - 扫描当日群消息里的 GitHub / Hugging Face / ModelScope 链接，按仓库去重并给出标题、简介与链接。
   - 若本机（repo-intro）已发过该仓库的总结卡片（带零宽水印），直接复用卡片里的 `📝` 标题与简介；
   - 裸链接交给 LLM 按 repo-intro 同一套规范补「一句话标题 + 60~120 字介绍」，条目不编造参数量/许可证/价格，拿不到就留空。

4. **新增「今日新闻」**：
   - 来源一：群内分享的微信公众号文章（按分享次数统计，复用 wechat-article-summary 已生成的标题与总结）。
   - 来源二：橘鸦 AI 早报当日一期（`news_feeds` 可配，默认 `rss.xml` + `issues/{date}/`，当天页缺失自动回退 RSS 最新一期）。
   - `news_event_merge` 开启时，用 LLM 把描述同一事件的公众号文章与早报条目合并成一条，并保留**全部来源链接**（公众号原文 + 早报来源）；失败自动降级为顺序罗列。
   - 条数上限由 `sections` 里 `news` 的第三段控制（默认 70）；标题自动带条数（`📰 今日新闻（12条）`），条目用中文序号「一、二、三、」。

5. **水印识别，不重复总结**：
   - 带 `Generated by JuanNiang Neo` 零宽水印的消息是本机插件产出，**不参与聊天分析**，只用来提取标题与已有总结；兼容旧版 4 字符标记。

6. **零图片依赖，极速轻量**：
   - 只用 OneBot 11 文本消息 / 合并转发，不依赖 T2I 渲染服务。

7. **后台全功能可视化配置**：
   - 多选群聊白名单、每日定时（默认 23:00，统计前 24 小时）、话题/金句/头衔/维度数量、人设强度、进度提示开关、一键立即触发。

8. **安全轻量的数据流**：
   - 专属消息表，默认保留 7 天轮转，分析后自动清理。

## 权限

`onebot11` `database` `llm` `agent` `timer` `cache` `http`（http 用于抓取橘鸦早报）
